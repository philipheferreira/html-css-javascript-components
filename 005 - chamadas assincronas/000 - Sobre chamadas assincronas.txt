1. O que é uma Chamada Assíncrona?

No mundo síncrono, o código é executado linha por linha. Se a linha 2 pede 
um arquivo gigante na internet, o código inteiro para ali e espera o download 
terminar para só então executar a linha 3.

No mundo assíncrono, quando o código encontra uma tarefa demorada (como buscar 
dados num banco de dados, ler um arquivo pesado ou fazer uma requisição HTTP), 
ele diz: "Não vou esperar por você. Vou delegar essa tarefa para o fundo (para 
o navegador ou o Node.js) e continuar executando as próximas linhas. Quando você 
terminar, me avise que eu volto para processar o resultado".


2. Os Tipos de Chamadas Assíncronas no JavaScript

A forma de lidar com assincronicidade no JS evoluiu muito ao longo dos anos. 
Existem basicamente três padrões (ou tipos) de se trabalhar com chamadas assíncronas:

A. Callbacks (O modo antigo)
Uma callback é simplesmente uma função que você passa como argumento para 
outra função, com a instrução de "chame de volta quando terminar".

Exemplo:

console.log("1. Iniciando");

setTimeout(function() {
    console.log("2. Tarefa assíncrona terminada (depois de 2 segundos)");
}, 2000);

console.log("3. Executando o restante do código...");

// Saída no console:
// 1. Iniciando
// 3. Executando o restante do código...
// 2. Tarefa assíncrona terminada (depois de 2 segundos)

O Problema: Se você tiver várias operações assíncronas que dependem uma da outra, 
você começa a aninhar funções dentro de funções. Isso gera o famoso Callback Hell 
(Inferno dos Callbacks), deixando o código ilegível e difícil de manter.

B. Promises (Promessas - O padrão ES6)

Para resolver o Callback Hell, o ES6 (2015) introduziu as Promises. Uma 
Promise é um objeto que representa o sucesso ou a falha eventual de uma 
operação assíncrona. Ela tem três estados:

* Pending (Pendente): Aguardando.

* Fulfilled (Resolvida): Concluída com sucesso.

* Rejected (Rejeitada): Falhou.

Você usa os métodos .then() (para o sucesso) e .catch() (para o erro).

Exemplo:

const minhaPromise = new Promise((resolve, reject) => {
    setTimeout(() => {
        let sucesso = true;
        if(sucesso) {
            resolve("Dados buscados com sucesso!");
        } else {
            reject("Deu erro na busca.");
        }
    }, 2000);
});

minhaPromise
    .then((resultado) => console.log(resultado))
    .catch((erro) => console.log(erro));

console.log("Código continua...");

Vantagem: Encadeamento linear (.then().then().catch()), muito mais limpo que os 
callbacks aninhados.

C. Async / Await (A forma moderna - ES2017)

É a forma mais atual e recomendada de escrever código assíncrono. Na verdade, 
é apenas "açúcar sintático" (syntax sugar) por cima das Promises. Ele faz o código 
assíncrono parecer e se comportar como código síncrono, o que facilita muito a leitura.

* async: Colocado antes de uma função, diz que ela retornará uma Promise.

* await: Só pode ser usado dentro de uma função async. Pausa a execução daquela função 
até que a Promise seja resolvida.
Exemplo:

async function buscarDados() {
    try {
        console.log("Buscando...");
        // O código pausa AQUI até que a Promise resolva
        const resultado = await minhaPromise; 
        console.log(resultado);
    } catch (erro) {
        console.log("Erro capturado:", erro);
    }
}

buscarDados();

3. Onde encontramos chamadas assíncronas na prática?
Você não cria a maioria das tarefas assíncronas do zero; você usa APIs nativas do 
navegador ou do Node.js que retornam Callbacks ou Promises. Os principais exemplos 
são:

1. Timers: setTimeout() e setInterval().
2. Requisições HTTP (Fetch API): Trazer dados de uma API externa.

// Fetch já retorna uma Promise nativamente
const response = await fetch('https://api.exemplo.com/dados');
const data = await response.json();

3. Leitura/Escrita de Arquivos (Node.js): Usar o módulo fs.promises para ler 
arquivos do disco sem travar o servidor.

4. Eventos (Event Listeners): Embora tenham uma natureza um pouco diferente 
(são reativos), cliques de botão ou digitação no teclado são processados de forma 
assíncrona pelo Event Loop.

5. Bancos de Dados: Bibliotecas como Prisma, Sequelize ou drivers do MongoDB usam 
Promises por baixo dos panos para salvar/buscar dados.

Resumo do Event Loop (A mágica por trás)

Como o JS é de uma thread só, quem faz o trabalho pesado é o ambiente (Navegador ou Node.js). O navegador tem "Web APIs" que processam o download em threads separadas. Quando a tarefa termina, ela vai para uma "Fila de Tarefas" (Task Queue). O Event Loop fica de olho nessa fila: sempre que a thread principal (Call Stack) ficar vazia, ele pega a próxima tarefa assíncrona finalizada e a joga na thread principal para ser executada.
